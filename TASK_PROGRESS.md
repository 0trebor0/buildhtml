## API coverage audit

A throwaway script (kept outside the repo, in the session scratchpad) walked the
public exports of `index.js` and their prototypes, then checked each name against
the full `test/` corpus. 432 members discovered; 38 never referenced by name:

- **32 private methods** (`_`-prefixed) on `Document`, `Element`, and
  `TemplateParser`. Reached indirectly — `TemplateParser`'s internals run under
  the `compile`/`parse` tests, and the `Element`/`Document` internals run under
  render and lifecycle tests.
- **6 public methods**, three names on both `Document` and `Element`:
  `caption()`, `ol()`, `tfoot()`. These are generic `TEXT_TAGS` shortcuts
  generated by the loop at `lib/shortcuts.js:39`, so they share their
  implementation with covered siblings (`ul`, `thead`, `legend`, ...).
  Manually smoke-tested: all three emit correct markup, in both the text and the
  setup-function forms.

## Notes and limitations

- Reference-by-name is a proxy for coverage, not proof of it. A name appearing
  in `test/` does not guarantee its behaviour is asserted; no line-coverage tool
  is configured in this project.
- `ol(['a','b'])` renders `<ol>a,b</ol>`, not list items. This is correct — the
  generic tag shortcuts take text or a setup function, and `list(items, renderer,
  tag)` is the array API. Verified `list(['x'], null, 'ol')` gives
  `<ol><li>x</li></ol>`.
